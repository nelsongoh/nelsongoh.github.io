docu-rag · A visual introduction to RAG

How AI answers
from documents.

I built docu-rag to learn how an AI can answer questions using information from documents. It uses a method called retrieval-augmented generation (RAG): find relevant information first, then give it to the AI to help it write an answer.

Why payments? Questions about payments often have specific, documented steps, so we can check an AI’s answer against the instructions. That makes payments a useful example for learning RAG. docu-rag uses Stripe’s payments documentation; this walkthrough uses a short, invented help page to keep the example easy to follow.

You do not need to know how payments or AI work. We will prepare that page for searching, then use it to answer the question below.

The task

01

Start with a question about a payment.

Imagine a shop owner wants to return part of a customer’s payment. They ask, “How do I issue a partial refund?”

The AI needs the relevant instructions to answer reliably. RAG finds those instructions and includes them in the message sent to the AI.

First, prepare the informationSteps 2–4 happen before questions are answered. Once the pages are prepared, steps 5–7 run for each question.

Prepare the information

02

Read a payments help webpage.

The panel shows a simplified webpage of payment instructions. The navigation says “Payments / Refunds”, and the section heading is “Partial refunds”.

docu-rag extracts the page’s text and keeps its headings and source link. Next, it breaks the text into smaller pieces that can be searched.

Our sample pageThe instructions are invented for this explanation. The real project collects Stripe documentation webpages.

Prepare the information

03

Split the page into smaller passages.

Each small piece of text is called a chunk. We will call the two pieces here Passage 1 and Passage 2. These labels simply help you follow them through the example.

Each passage keeps the headings from step 2: “Payments → Refunds → Partial refunds”. That tells us where it came from. One sentence appears in both passages so the split does not lose the connection between the instructions.

NextWe make these passages searchable by meaning, so the question does not have to use exactly the same words.

Prepare the information

04

Create a number pattern for each passage.

docu-rag sends each passage to an embedding model from OpenAI. This model returns a list of numbers called an embedding. Text with similar meanings tends to produce similar number patterns.

These number patterns are called vectors. A vector database is designed to store them and search for similar patterns, while keeping each one linked to its original passage and source details. docu-rag uses ChromaDB as its vector database. The map illustrates similarity; select a point to read its passage.

The information is readyThis prepares a search index. It does not train the answering AI on the page. Next, we return to the shop owner’s question.

Answer the question

05

Find passages that could answer it.

Now when the shop owner asks about a partial refund, docu-rag uses the same embedding model to turn the question into numbers, then looks for passages with similar number patterns (vector search).

It also searches for matching words in the text and headings (BM25). It combines the two result rankings (Reciprocal Rank Fusion, or RRF) and selects passages to give to the answering AI.

The technical names

The meaning search compares embeddings. The word search uses BM25. Reciprocal Rank Fusion combines their rankings. This walkthrough shows illustrative results, not measured search scores.

Answer the question

06

Send the question and passages to the AI.

Finding passages and writing an answer are separate jobs. docu-rag now creates a prompt: the message sent to the AI that writes the answer.

The message contains instructions, the original question, and the passages found in step 5. The AI can use this information when answering, rather than relying only on what it learned during training.

What RAG addsThe retrieved passages are the extra information added to the question. The full collection of documents is not sent with every question.

Answer the question

07

Read the answer and check the source.

The AI uses the supplied passages to write an answer. A numbered citation, like [1], points to the source behind it.

Select [1] to compare this sample answer with the help page we started with. You can trace the information all the way from the original page to the answer.

What this does not guaranteeA search can miss useful information, the page can be wrong, or the AI can misread it. Citations help us check an answer; they do not prove it is correct.

Project note

Why I built docu-rag.

I wanted to understand how to search documents, give an AI useful information, and let a reader check where an answer came from. docu-rag is my learning project, built with Claude Code. The scenes above explain its approach using a simplified example; they are not a live run of the app.

This version uses Anthropic’s Claude to write answers. The same approach can be adapted to most other large language models (LLMs) by changing the model integration.
